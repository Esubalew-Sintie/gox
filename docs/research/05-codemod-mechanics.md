# How Go code generators safely modify existing source — research for gox

## Recommendation for gox
Stop editing files; regenerate tool-owned files from a manifest, and never touch user-owned files. This is the pattern every durable Go generator converged on (sqlc, ent, goa, oapi-codegen, goctl, wire). Marker insertion survives only as a narrowly-scoped fallback.

1. Two file classes, by name and header.
   - Tool-owned (regenerated wholesale, always): the composition root. Rename initiator/{handler,module,persistence,routes}.go to *_gen.go with first line `// Code generated by gox. DO NOT EDIT.` (must match `^// Code generated .* DO NOT EDIT\.$` before first non-comment text so golangci-lint and gopls treat them as generated). Also tool-owned: config_gen.go. Nothing else.
   - User-owned (generated once, never written again): every module file (handler/service/repository/model/dto/routes), main.go, config.go. Precedents: go-swagger configure_*.go ("safe to edit"), goa example, goctl logic/.
   - Rewrite only via explicit `gox generate --force <path>` showing a diff first.
2. Contract between classes is a Go convention, not a text anchor. Each module exposes stable entry points the generated root calls: `func New(deps Deps) *Handler`, `func (h *Handler) Routes(r Router)`, `func NewRepository(db DB) Repository`. Generated root is an ordinary explicit DI graph with zero reflection. User config stays user-owned by embedding the generated struct (`type Config struct { GeneratedConfig; ... }`), so adding a module never edits config.go.
3. Manifest is the source of truth: gox.yaml (user-editable intent) + .gox/manifest.json (tool state). Precedents: Kubebuilder PROJECT file (records cliVersion, every scaffolded resource, exists "to automate re-scaffolding"); cruft .cruft.json (template commit hash + skip list); openapi-generator .openapi-generator/FILES + ignore. Store per generated file: path, class (tool|once), gox version, template id, sha256 of content as written.
4. Idempotent add/remove. `gox add module order` = edit gox.yaml -> regenerate all *_gen.go from scratch -> write module files only if absent. `gox remove module order` = remove from gox.yaml -> regenerate roots -> delete module dir only if each file's hash still equals recorded hash; otherwise leave and print what to delete. Regeneration is a pure function of (manifest, templates, gox version).
5. Refuse to clobber. Before writing any tool-owned file: if exists and hash != manifest hash -> abort with diff, exit 1, unless --force or --adopt (convert to user-owned). Never delete a file lacking the Code generated header (ent's cleanOldNodes deletes by filename pattern only; avoid). Ship `gox check` (= sqlc diff) for CI: regenerate to memory, diff against disk, non-zero on drift.
6. Transactional apply. Plan every write in memory first; require clean git tree or --allow-dirty; back up originals; write via temp+rename on same filesystem (renameio pitfalls: same mount, no Windows atomicity); run imports.Process on each Go output; then go build ./... && go vet ./...; on failure restore backups and exit. Pin gox in target project via Go 1.24 tool directive.
7. Where you must edit a user-owned file (ideally nowhere): AST-located text edits: parse with go/parser to find byte offsets, splice bytes, run imports.Process. Never round-trip through go/printer. This is what kubebuilder, NestJS MetadataManager, cmd/cover, and Go 1.26 go fix do. Current gox injectImport/removeImport violate this.
8. Templates: text/template + imports.Process (ent, oapi-codegen, kubebuilder); embed defaults; per-project override dir .gox/templates/<same relative path>; `gox templates publish` and `gox templates diff`.
9. Do not depend on Wire (archived 2025-08-25) nor init() registration.

## Mechanism comparison table
| Criterion | Markers + text insert + gofmt (gox today, kubebuilder, Buffalo, Rails) | go/ast + go/printer | dave/dst | AST-located byte edits + imports.Process | Tool-owned files regenerated from manifest | Scan-and-regenerate registry (wire, controller-gen) | init()/blank-import |
|---|---|---|---|---|---|---|---|
| Idempotent | Only with dedupe (kubebuilder trimmed window; Buffalo none) | If checked | Yes | Yes | Inherently | Yes | N/A |
| Reversible | Fragile (Thor revoke regex) | OK, comments orphaned | Good | Good | Trivial | Trivial | Delete file |
| User hand-edited | Survives outside markers; moved markers break | Survives, may reflow | Survives | Survives | Detect via hash, refuse | Same | N/A |
| Formatting/comments | Preserved outside region | Comments displaced, blank lines lost (golang/go#20744) | Preserved | Preserved | N/A | N/A | N/A |
| Failure modes | Marker missing, duplicates, indentation | Comment drift | Resolver issues, node reuse panics | Stale offsets | Stale files without manifest cleanup; wrong deletion if header unchecked | Needs type-checkable package (fails when build broken); slow | Order-dependent, hidden |
| Complexity | Low | Medium | Medium + dep | Low–medium | Low | High | Low |
| Trust | Medium | Low | Medium | Medium–high | High with hashes + header | High | "magic" |

## Evidence per tool
- gox (current): injector inserts text at markers and runs format.Source (fine). Imports go through go/ast append/delete + format.Node. Experiment reproducing removeImport on an import with doc and trailing comment: both comments left behind and attach to the NEXT import; deleting a middle spec leaves a stray blank line. containsInjectedCode is substring-based, so a commented-out line counts as present (same bug Rails documented for routes).
- Kubebuilder pkg/machinery: markers `// +kubebuilder:scaffold:<x>`; fragments inserted before marker; dedupe via trimmed line windows; imports.Process. Docs warn moving markers breaks scaffolding. They had to build PROJECT manifest, alpha generate (re-scaffold from PROJECT), alpha update (3-way git merge). The mature end state of markers is manifest-driven regeneration.
- Buffalo genny gogen: AddInsideBlock searches literal "appOnce.Do(func() {", splices with hardcoded tabs, no duplicate check, no gofmt; AddImport line-splices, no dedupe, panics on zero/single-line imports. CLI last tagged v0.18.14 (Feb 2023).
- Rails/Thor: inject_into_file reversible by regex; commented-out route "detected as present"; 2015 fix for routes.rb corruption on revoke.
- NestJS MetadataManager: TS AST for positions, then string splicing; partial whitespace handling; duplicate checks.
- go/ast + go/printer: go/ast docs warn comments must be updated manually; golang/go#20744 (2017, still open); 2026 CL "lossless comments" not landed.
- dave/dst: v0.28.0 (2026-09-10), go 1.26.0, 393 importers, stable. Caveats: node reuse panics, dot-import resolver panic, gopackages resolver slow. Viable but single-maintainer and unnecessary if you don't reprint user files.
- astutil: AddImport returns added=false if present; DeleteImport deletes duplicates; no comment handling. gopls CLI codeaction -exec experimental.
- go fix (1.26): analyzers emit TextEdits applied textually; final pass removes unused imports.
- Wire: archived 2025-08-25; wire_gen.go header + go:generate. kratos-layout still uses it; users add constructors to ProviderSet by hand.
- sqlc: header + versions; `sqlc diff` in CI.
- ent: schema user-owned; everything else regenerated; imports.Process; customization via --template, gen.Hook, never editing output. cleanOldNodes deletes stale files by filename without header check.
- oapi-codegen: text/template + imports.Process ("generation code produces unindented horrors"); user implements ServerInterface in own file; commit generated code and verify in CI.
- goctl: "only overwrites files it owns (handler/, types/, routes.go). logic/ preserved."
- go-swagger/goa: generate-once configure file; goa gen wipes gen/.
- gqlgen: internal/rewrite slices method bodies as raw bytes and re-emits; moves deleted code into a WARNING block. Only needed if regenerating files containing user code.
- init() registration: Uber guide "Avoid init()"; Google guide treats global registries as problems. Blank imports hide dependencies, defeating gox's explicitness principle.
- Template engines: text/template + imports.Process de-facto standard (ent, oapi-codegen, kubebuilder, sqlc), readable/overridable. jennifer (v1.7.1 Sep 2024) abstract API, not file-overridable. quicktemplate for HTML. templ for UI. gofumpt optional stricter pass after imports.Process.

## Pitfalls
1. Substring/regex presence checks accept commented-out code -> duplicates.
2. Reprinting whole *ast.File to edit one import strands comments (reproduced in gox removeImport). Stop using format.Node on user files.
3. Deleting stale files by name without header check can delete user code.
4. Markers inside user-owned files make the user responsible for the tool's anchors.
5. Hand edits in tool-owned files silently lost unless hashes tracked: the #1 trust killer.
6. Scan-based discovery fails exactly when the project doesn't compile.
7. Non-atomic multi-file writes leave half-wired project if go build fails midway.
8. Floating tool versions change output; pin with tool directive, record gox version.
9. imports.Process can drop an import when referencing code isn't written yet; generate call site and import together.
